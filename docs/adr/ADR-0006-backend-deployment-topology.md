# ADR-0006: 后端部署拓扑 — 模块化单体，暂不引入微服务网关

- **状态**：已采纳（2026-08-29）
- **决策人**：Linda
- **关联**：ADR-0002（基础设施层轻量授权）、ADR-0003（B 端租户与配额）、local-dev-env（单实例基础设施）、project-architecture（仓库拆分约定）

## 背景

后端接口部分是否需要现在引入微服务网关（Spring Cloud Gateway / APISIX / Kong），还是单体服务即可。

项目当前真实状态：

- 仓库已按职责**物理拆分**为独立 GitHub 仓：`liganex-studio/backend`（鉴权 + 会话编排 + MCP 代理）、`liganex-gen`（模型抽象 + 异步任务 + 配额 + 资产）、`liganex-mcp`（MCP server）、`liganex-hub`（开放平台）。这已是**部署级隔离**，不是单一巨型单体。
- B 端采用**单一前端入口**（`liganex-studio/frontend`），由 `studio/backend` 充当聚合 / 编排 / 鉴权层；API Key 鉴权经应用内 Spring Security filter 落地（ADR-0002/0003），无需网关层卸载。
- 本地基础设施为**单实例栈**（Postgres+pgvector / Redis 8 / RocketMQ 5，经 OrbStack），服务数量目前为 1–3 个后端 + 单前端。
- 项目定位为开源求职项目，处于早期开发阶段，尚未有真实多租户生产流量与独立扩缩容压力。

## 决策

后端采用**模块化单体（modular monolith）**拓扑，**当前阶段不引入独立的微服务 API 网关**。

跨切面关注点的处理方式：

| 关注点 | 处理方式（不引入网关） |
|---|---|
| TLS / 路径路由 / 统一入口 | 部署级反向代理（nginx，本地已配置），仅做 TLS 终结与按路径转发 |
| 鉴权（API Key） | 应用内 Spring Security filter（ADR-0002/0003），各后端自管 |
| 限流 | 基于已选型的 Redis 8 实现，不依赖网关组件 |
| 服务间调用 | `studio/backend` 直接调用 `gen` / `mcp` 等，经 HTTP 或 SDK，无需服务发现 |
| 模块边界 | 在 `studio/backend` 内部按 auth / session / mcp-proxy / billing-quota 划分子模块，边界清晰、可独立测试 |

`studio/backend` 内部须保持**清晰的模块边界与单向依赖**，使未来可将任一模块（如 billing-quota、mcp-proxy）提取为独立服务时无需重写，而非提前拆成网络隔离的微服务。

## 理由

- **YAGNI / 避免过早复杂化**：微服务网关的红利（集中路由、鉴权卸载、服务发现、跨服务限流熔断、金丝雀）只有在「多个独立部署、独立扩缩容的服务」场景下才划算。当前 1–3 个后端 + 单前端，引入网关等于新增一个部署物、一个安全面、一份配置漂移，收益近零。
- **已有聚合层**：B 端单入口已由 `studio/backend` 承担编排与鉴权，其上再叠网关属重复建设。
- **物理拆分已提供隔离**：仓库级拆分已满足「独立构建、独立部署」诉求，网关解决的问题与之不同，不应混淆。
- **运维与稳定性**：本地栈已含 PG/Redis/RocketMQ，少一个网关组件即少一处故障面，契合「稳定优先」原则（见 config 稳定与探索平衡约定）。
- **求职项目加分点**：一个模块边界清晰、且明确「何时该引入网关、如何渐进拆分」的模块化单体，比半成品网关更能体现分布式系统判断力。

## 边界与触发条件

本 ADR 覆盖当前阶段（早期开发、单实例基础设施、服务数 ≤ 3）。一旦出现以下任一情况，应重新评估引入 API 网关（Spring Cloud Gateway / APISIX）或 service mesh：

- 后端服务数增长至 **> 3–4 个**且各自有不同扩缩容节奏
- `gen` 与 `studio/backend` 需要独立团队 / 独立部署 / 独立扩缩
- 需要在网络层做**强租户隔离**或跨服务统一熔断 / 金丝雀 / 按路由策略
- 出现大量跨服务调用，手工 URL 配置与鉴权转发成为明显负担

届时以独立 OpenSpec change 引入网关，且优先 APISIX 等云原生方案而非自研。

## 后果

面试被问「为什么没用微服务网关」时，可说明：仓库已物理拆分满足部署隔离；B 端聚合层已承担鉴权与编排；网关红利尚未到兑现阈值；并已定义明确的触发条件与渐进拆分路径——展示对「何时该上分布式、何时不该」的判断，而非盲目堆架构。
