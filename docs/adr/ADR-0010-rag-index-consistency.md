# ADR-0010：RAG 索引边界与数据一致性

- 状态：Accepted
- 日期：2026-08-30
- 关联：ADR-0003、ADR-0004、ADR-0005、ADR-0006、ADR-0007、ADR-0008

## 背景

知识库需要同时保存原文、解析结果、检索分块和向量。若业务数据与向量库各自写入，删除、失败重试和用户隔离容易出现双写不一致。本期还需要为后续评估 Qdrant 或 Redis 保留边界，但不应为尚未发生的切换增加三套实现成本。

## 决策

1. Postgres 是知识文档、分块、索引状态、会话和消息的事实来源；本期使用同库 pgvector。
2. 业务层只依赖 `KnowledgeIndex` 端口。端口的写入、检索和删除均强制包含登录用户 ID 与知识库范围；本期只注册 `PgVectorKnowledgeIndex`。
3. 配置为未实现的 Qdrant 或 Redis 时明确启动失败，不静默回退。
4. 文档处理通过持久化任务表领取和重试。稳定 chunk ID 与唯一约束保证重放幂等。
5. 删除先让文档退出可检索状态，再在同一数据库事务中删除分块和原文。未来外部对象清理由可重试 Outbox 承担。
6. 切换向量后端或 Embedding 模型必须从 Postgres 重建目标索引，校验 owner 过滤、数量、维度和抽样召回；目标 READY 前不得承接读取。

## Qdrant / Redis 重评估条件

- pgvector 在真实过滤条件下无法满足已约定的 P95 延迟或召回基线；
- 向量容量、写入吞吐或独立扩缩需求明显超过主业务数据库能力；
- 已完成目标适配器、重建工具、双用户隔离测试和回滚方案。

Redis 仅在明确采用独立索引实例且容量、持久化与召回评测达标时考虑，不能复用当前缓存实例作为知识向量主存储。

## 结果

本期部署简单，删除可原子化，索引与业务数据不需要跨系统补偿。代价是向量负载与 OLTP 同库，需要通过查询基准、连接池和索引参数持续观察；规模达到阈值后再按上述迁移流程切换。
